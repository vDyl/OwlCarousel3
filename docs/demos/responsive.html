Overview

Responsive option can be used for setting breakpoints and additional options within. Try changing your browser width to see what happens with Items and Navigations.

About responsive option

Setting of the responsive is very simple. Structure of responsive option:

responsive : {

	// breakpoint from 0 up
	0 : {
		option1 : value,
		option2 : value,
		...
	},

	// breakpoint from 480 up
	480 : {
		option1 : value,
		option2 : value,
		...
	},

	// breakpoint from 768 up
	768 : {
		option1 : value,
		option2 : value,
		...
	}
}

Key facts:

  • Each breakpoint key can be a number, such as 480, or a numeric string, such as '480'.
  • Breakpoints are evaluated numerically, but it is clearest to list them from the smallest screen to the widest.
  • Responsive options override matching top-level settings.
  • The default is an empty object. Without breakpoint entries, the top-level options are used.
  • Set responsive:false when you want to disable breakpoint handling.

Live Example

$('.owl-carousel').owlCarousel({
	loop:true,
	margin:10,
	responsiveClass:true,

	responsive:{
		0:{
			items:1,
			nav:true
		},
		600:{
			items:3,
			nav:false
		},
		1000:{
			items:5,
			nav:true,
			loop:false,
			margin:20
		}
	}
})

Responsive related options:

responsiveClass

Optional helper class. Adds owl-responsive-<breakpoint> to the main element.

responsiveBaseElement

As default all responsive breakpoints are corresponding with window width. This option gives you an opportunity to change it to your own class/id like responsiveBaseElement:".myCustomWrapper"

responsiveRefreshRate

After a resize, Owl waits for responsiveRefreshRate milliseconds before recalculating the layout. The default is 200.

Breakpoint objects override top-level settings. Options that create markup or register behavior during initialization may require a manual refresh when changed after initialization.
